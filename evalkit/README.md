### 1. 채점 — 실패는 0 점이 아니다

```python
def call(prompt):                      # 여러분의 LLM 호출
    return llm.invoke(prompt).content

def prompt_of(q):
    return JUDGE_PROMPT.format(q=q["질문"], ref=q["정답"], ans=answer(q))

ss = score_all(questions, prompt_of, call, label_of=lambda q: q["id"])
print(ss.mean, ss.by([q["유형"] for q in questions]))
for label, why in ss.failures:
    print("심판 실패:", label, why)
```

`judge()` 는 호출이 터지거나 응답을 못 읽으면 `score=None` 을 돌려준다.
**0 점이 아니다.** 0 으로 처리하면 심판이 죽은 만큼 평균이 조용히 낮아지고,
그 사실이 어디에도 남지 않는다. 실패는 평균에서 빠지고 건수로 보고된다.

### 2. 반복 — 한 번 재고 방향을 말하지 않는다

```python
m = measure("pr=10", lambda: score_all(...), reps=3)
print(m)     # pr=10: 3.44 (폭 0.07 · 3회: 3.47, 3.47, 3.40)
```

`Measurement` 를 1회만 재면 문자열이 이렇게 나온다:

```
한번만 잰 값: 3.90 (1회 — 편차를 모르므로 이 값으로 비교하지 말 것)
```

### 3. 항목별 흔들림 — 평균만 보면 안 보이는 것

```python
m = measure("통과율", run_once, reps=3)
m.print_items()
```

```
  [회차마다 결과가 달라진 항목 3개] — 비교 근거로 쓸 수 없다
    C-004  3회 중 1회 통과
  [매번 실패 2개] — 진짜 고칠 곳은 여기다
    C-019, C-027
```

"39건 중 36건 통과"가 매번 **같은** 36건인지 회차마다 **다른** 36건인지는 평균에 안 나온다.
둘은 완전히 다른 상황이다. 소울매트 CS 에이전트에서 먼저 만든 것을 올려 왔고,
올리고 나니 거기 라우터가 처음으로 이 분석을 받아 매번 틀리는 3건이 드러났다.

`run_once` 가 `{항목: 점수}` dict 나 `ScoreSet` 를 돌려주면 자동으로 잡힌다.

### 4. 비교 — 구분되는 것만 구분된다고 말한다

```python
compare({
    "예산 10": lambda: run(per_relation=10),
    "예산 20": lambda: run(per_relation=20),
}, reps=3)
```

```
── 3회씩 측정 ──
  예산 10: 3.44 (폭 0.07 · 3회: 3.47, 3.47, 3.40)
  예산 20: 3.40 (폭 0.20 · 3회: 3.27, 3.47, 3.47)

  '예산 10' 가 가장 높지만 '예산 20' 와는 구분되지 않는다 (차이가 편차 안).
  → 구분되지 않으면 점수로 고르지 말고 비용·단순함으로 고를 것.
```

`distinguishable(a, b)` 의 기준은 **차이 > 두 측정 중 큰 폭**이다.
엄밀한 검정이 아니라, 3~5회로 방향을 말해도 되는지 거르는 최소 관문이다.

## 왜 이렇게 되어 있는가 — 실제로 당한 것들

**① 한 번 재고 방향을 말할 뻔했다.** (2026-09-18)
탐색 예산을 올렸더니 3.67 → 3.47 로 내려갔다. "많이 담으면 나빠진다"고 쓰려는데,
같은 설정을 3회 다시 돌려 보니 **편차 자체가 0.20** 이었다. 두 설정의 실제 차이는
0.04 였다. → `measure`, `distinguishable`

**② 기능을 껐는데 안 꺼져 있었다.** (2026-09-18)
연도 필터의 A/B 를 짜면서 필터만 끄고, 그 기능이 근거에 남기는 연도 **표기**는
그대로 뒀다. 사실은 같은 조건 둘을 비교하고 "차이 없음"이라 결론 낼 뻔했다.
3단으로 갈라 보니 효과의 대부분이 필터가 아니라 표기에서 나왔다.
→ `compare` 의 docstring 경고. **끄는 쪽은 그 기능이 흘리는 정보까지 전부 꺼야 한다.**

**③ 기본값이 안 바뀌었다.** (2026-09-18)
`def f(x, budget=BUDGET)` 는 기본값을 **정의할 때 한 번** 계산해 묶는다.
실험 코드에서 모듈 변수를 바꿔도 반영되지 않아, "두 설정 비교"가 실은 같은 설정을
두 번 돌린 것이었다. 삼중항 개수가 똑같아서 겨우 들켰다.
→ evalkit 이 막아 줄 수 없는 종류다. **arm 마다 실제로 값이 달라졌는지 지표 하나를
같이 찍어 확인할 것.**

**④ 심판을 길게 가르칠수록 나빠졌다.** (2026-09-17, 소울매트 챗봇)
판정 규칙을 한 줄 넣자 19/23 → 11/23, 예외까지 적어 여섯 줄로 늘리자 8/23 이 됐다.
세어 보면 아는 것(숫자가 근거에 있는가, 문장이 들어 있는가)은 심판에게 묻지 말고
코드로 판정한다. 심판은 **판단이 필요한 것에만** 쓴다.

**⑤ 심판은 생성 모델과 다르게 둔다.** 생성 gpt-4.1-mini / 심판 gpt-4.1.
같은 모델로 채점하면 자기 답을 후하게 본다.
